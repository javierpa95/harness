# Design Inspiration

Fuente de referencia para el agente de diseno. Usa estas fuentes para buscar inspiracion real y anclar tus decisiones ANTES de proponer o escribir `docs/design.md`.

## Regla de oro

No inventes una identidad visual de memoria. **Busca en las fuentes de abajo**, analiza ejemplos de exito del dominio del producto y adapta patrones que ya demostraron funcionar.

## Galerias / patrones de UI

| Fuente | Para que |
|--------|----------|
| [Mobbin](https://mobbin.com) | Patrones de apps moviles y web reales, por categoria/flujo |
| [Dribbble](https://dribbble.com) | Exploracion visual y tendencias de diseno |
| [Behance](https://www.behance.net) | Portafolios y exploracion por disciplina |
| [Laws of UX](https://lawsofux.com) | Principios/leyes de UX (Jakob's law, Hick's law, etc.) |
| [Refactoring UI](https://www.refactoringui.com) | Principios practicos de diseno UI |
| [Awwwards](https://www.awwwards.com) | Mejores sitios web del mundo (premiados) |
| [UI Patterns](https://ui-patterns.com) | Patrones de interfaz clasificados por problema |

## Flujo de trabajo recomendado

1. Identifica el **tipo de producto** (e-commerce, SaaS, mobile app, dashboard, etc.).
2. Busca en **Mobbin** / **Dribbble** / **Awwwards** patrones de EXITO de ese dominio.
3. Extrae 3-5 patrones concretos (paleta, layout, componentes de ese tipo de app).
4. Valida el contraste/convenciones con las fuentes de accesibilidad.
5. Propone y justifica en `docs/design.md` cada decision con una referencia.

## Si una fuente esta caida o no hay resultado

Usa **websearch** con terminos especificos (ej. "best dashboard UI patterns 2025", "mobile checkout UX best practices") y cita lo que encuentres. La skill es una base, no un limite — el objetivo es que la propuesta este fundada en ejemplos reales.
